D) OPTIMIZACIONES APLICADAS
===============================================================================

D.1 - PHP/OPcache (php.ini mount en /usr/local/etc/php/conf.d/zz-app.ini)
    opcache.enable = 1
    opcache.memory_consumption = 256
    opcache.max_accelerated_files = 20000
    opcache.interned_strings_buffer = 32
    opcache.revalidate_freq = 60
    opcache.jit = 1255
    opcache.jit_buffer_size = 128M
    realpath_cache_size = 4M
    realpath_cache_ttl = 600
    memory_limit = 256M
    output_buffering = 4096     # necesario para que Caddy pueda comprimir
    display_errors = Off
    error_reporting = E_ERROR | E_PARSE

D.2 - Compresion HTTP (Caddyfile mount en /etc/frankenphp/Caddyfile)
    encode zstd gzip    # elige el mejor segun Accept-Encoding del cliente

D.3 - Cache headers para assets estaticos
    Cache-Control: public, max-age=2592000    (30 dias)
    Aplica a: .css .js .jpg .jpeg .png .gif .svg .webp .avif .woff .woff2 .ttf .ico

D.4 - UTF-8 BOM removido de a-includes/Funciones.php
    Los 3 bytes del BOM (EF BB BF) al inicio del archivo forzaban
    flush temprano del output y Caddy no podia buferear para comprimir.

D.5 - Endpoints JSON del checkout (initPagos.php, initPaymentPaypal.php)
    display_errors=0 + error_reporting=E_ERROR|E_PARSE para evitar que
    warnings Deprecated del SDK Stripe 7.x y Guzzle contaminen el body
    JSON y rompan el parser de jQuery (antes causaba "ERROR CON EL
    SERVIDOR" al pagar).

E) FIXES APLICADOS DURANTE LA SESION (historico relevante)
===============================================================================

E.1 - Conexion DB: a-includes/conexion.php lee env vars MYSQLHOST/USER/
      PASSWORD/DATABASE/PORT de Railway (linkeadas con ${{MySQL.*}}).

E.2 - Docker: nixpacks.toml no instalaba pdo_mysql. Switch a Dockerfile
      custom con FrankenPHP base + install-php-extensions.

E.3 - SQL injection parcheada en getIP/insertIP/updateIP (prepared
      statements). Antes rompia con json_encode($_COOKIE) con chars
      unicode.

E.4 - ip_visita.id_producto ampliado de varchar(16) a varchar(64)
      (italiano_pack_experto no entraba).

E.5 - Geolocalizacion (logicparametros.php): acceso seguro a
      HTTP_CF_IPCOUNTRY con isset, lookupIpdataSafe() con try/catch
      para evitar bug del destructor de Symfony HttpClient
      (curl_multi_setopt CURLMOPT_PUSHFUNCTION).

E.6 - Endpoints Stripe/PayPal: autoload path correcto
      /a-libraries/vendor/autoload.php (donde viven los SDKs).

E.7 - checkout-stripe.js: URL Ajax de /latam/includes/initPagos.php
      a /a-includes/initPagos.php (legacy path ya no existe).

E.8 - initPagos.php: urlLib/urlCurso sin /latam/, slug tomado del
      path actual del browser (fix cancel_url que iba a 'ingles-dos'
      en lugar de 'ingles-nivel-dos').

E.9 - pago_exitoso.php + unirse.php: isset() en params GET + redirect
      al root si faltan (antes Warning "Undefined array key").

E.10 - Case-sensitive filesystem (Linux vs Mac): rename
       funciones.php -> Funciones.php para matchear las referencias
       ../a-includes/Funciones.php del codigo latam.

E.11 - FrankenPHP routing: symlink /app/public -> /app para evitar
       path duplicado /app/public/public/... cuando se solicitaban
       paginas de subdirectorios.

E.12 - SERVER_NAME=:80 + PORT=8080 variables en Railway, EXPOSE 8080
       en Dockerfile, para que el container escuchara en la interfaz
       correcta y Railway lo alcanzara sin 502.

E.13 - a-includes/logicparametros.php tenia dependencia a
       /vendor/autoload.php pero vendor real (con ipdata SDK) esta en
       /a-libraries/vendor/. Path corregido.

E.14 - Dockerfile con railway.json explicito que forza
       builder=DOCKERFILE (antes Railway usaba Nixpacks por default
       y no aplicaba mis cambios).
